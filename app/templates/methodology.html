Data & methodology

Why this page exists

An earlier version of this project used only Gender and Hemoglobin and reported ~100% accuracy on 5+ models. That wasn't a modeling achievement — Hemoglobin turned out to be a deterministic threshold function of the label with zero overlap, and 62% of the source rows were exact duplicates contaminating the train/test split. Full history: analysis/FINDINGS.md. Rather than presenting inflated metrics, this project was redesigned around a richer CBC feature space and a leakage-aware evaluation methodology — documented below.

Feature engineering

All 14 CBC features are numeric with no missing values after cleaning. Preprocessing is a single ColumnTransformer step (median imputation + standard scaling), fit only on the training split inside a scikit-learn Pipeline — never on validation or test data, and never outside the pipeline where it could leak information across the split.

Evaluation strategy

  • A stratified 80/20 holdout is carved out before any model selection or tuning happens, and is never touched until the single final evaluation.
  • Model selection uses 5-fold stratified cross-validation on the remaining 80%, scored on macro-F1 (not accuracy) because the classes are imbalanced.
  • The CV winner is tuned with RandomizedSearchCV, still restricted to the training split.
  • The held-out test set is evaluated exactly once, with the tuned pipeline, to produce the numbers on the Model Performance page.

Data drift monitoring (offline demonstration)

scripts/drift_report.py runs a per-feature two-sample Kolmogorov-Smirnov test comparing two real feature distributions — there's no live production traffic to monitor here, so this is a demonstration of the mechanism, not a live dashboard. By default it compares the training split against the held-out test split (expected result: no drift, since both are stratified samples of the same data — a sanity check on the test itself). Run python -m scripts.drift_report --classes "Healthy" "Iron deficiency anemia" to see it correctly flag real drift between two genuinely different patient populations (HGB and MCH show the strongest shift, consistent with how iron deficiency anemia is clinically distinguished).

Limitations

  • Small dataset for two classes. Macrocytic anemia (16 rows) and Leukemia with thrombocytopenia (10 rows) have very few examples — their per-class metrics carry wide uncertainty.
  • Manually diagnosed, single-source data. The dataset description states diagnoses were made manually from CBC values; this hasn't been validated against a second, independent clinical dataset.
  • Not a diagnostic tool. This reproduces patterns in a labeled dataset; it does not replace a clinician's diagnosis and has not been through any clinical validation process.
  • Physiologically-implausible-row filtering uses fixed reference ranges (see src/data/validate_data.py) — generous enough to keep genuine extreme pathology, but a judgment call, not a formally validated clinical threshold set.
